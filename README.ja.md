## v2.24.0 リリースノート

本バージョンは**サイト全体の国際化アーキテクチャの着地**をみた重要なアップデートです。自作の軽量 i18n フレームワークにより、简体中文 / 繁體中文 / English / 日本語 の 4 言語でフロントエンド UI、バックエンドのエラー応答、AI プロンプト、記憶抽出をすべてカバーしました。また、スマート翻訳の翻訳先言語は中国語に固定せず、UI 言語に追従するようになりました。

### 1. 4 言語対応フレームワーク（第三者依存ゼロ）

- **自作 i18n、URL プレフィックスなし**：言語の偏好は `localStorage` と同名の Cookie に保存され、切り替えは即座に反映されてルーティング遷移も発生しません。国際化ライブラリへの依存がないため、バンドルサイズも初回表示のオーバーヘッドも影響を受けません。
- **4 層を完全にカバー**：フロントエンドの UI 文言、バックエンドの HTTP エラー応答、AI システムプロンプトのフレーム、長期記憶の抽出と検索トリガーを、すべて言語ごとに描画します。
- **型レベルのキー名検証**：`t("...")` のキーはコンパイル時に検証されるリテラル union であり、1 文字でも打ち間違えれば即座にコンパイルエラーになります。実行時に `nav.chta` を無言で描画してしまうことはありません。4 つの辞書テーブルは構造の整合が強制されるため、ある言語の書き漏らしは一目で分かります。
- **ローカライズ整形**：日付、曜日名、数値、通貨、ファイルサイズ、相対時間（「3 時間前」/「3 hours ago」）のすべてが UI 言語に追従します。

### 2. 3 箇所の言語切り替え導線

- **ログインページのトップバー**：未ログイン時の唯一の導線です。英語圏のユーザーは**エラーメッセージを見る前に**言語を切り替えられる必要があります。
- **デスクトップのトップバー**：テーマ切り替えボタンのすぐ左に位置し、ログイン後は常設の導線です。先に設定を開く必要はありません。
- **環境設定 · 外観**：1 行の形式で説明文つき。選択肢は自言語の自称 + 英語名を並記しており、相互に確認できます。

### 3. スマート翻訳の翻訳先言語は UI 言語に追従

- **自前の言語は UI で決まる**：英語 UI なら英語へ、日本語 UI なら日本語へ、繁体字中国語 UI なら繁体字中国語へ翻訳します。従来はプロンプトに「中国語 ⇋ 翻訳先言語」とハードコードしていたため、英語用户在英語 UI で英語を入力しても中国語が返っていました。
- **同一言語なら自動的に単方向へ**：英語 UI で英語、日本語 UI で日本語を選ぶと、自動的に「任意の外国語 → 自前の言語」という単方向翻訳へ切り替わります。「英語を入力したら英語に翻訳する」といった矛盾した指示が生成されることはありません。簡体字中国語と繁体字中国語も同一言語として扱います。
- **バナーと言語チップの同期**：モードバナーと言語ボタンの「自前 ⇋ 翻訳先」表示が UI 言語にリアルタイムで追従します。固定で「中」と表示されることはなくなりました。

### 4. AI プロンプトの二言語戦略

- **フレーム部分は言語に追従**：既定のペルソナ、セクション見出し、時刻基準の説明、ウェブ検索の誘導、排版規約を 4 言語それぞれで文として記述します。時刻基準の説明は、モデルが「今日は何曜日ですか」に答える際に中国語の「星期三」を使うか英語の「Wednesday」を使うかを直接決定します。
- **ガードレール部分は中国語を維持**：推論の罠を防ぐガードレールの few-shot 例は、中国語固有の曖昧性を意図的に選んだものです（『水滸伝』の倒抜垂楊柳、「小美の弟は姉妹が何人いますか」の中国語語順の曖昧性、漢字の画数カウント）。英語の例に置き換えると別のアンカーセットになるだけで、このモジュールの価値はまさにその数本の例にあります。
- **先頭と末尾に 1 枚ずつ言語指示を注入**：先頭の指示はユーザー定義のペルソナとガードレール内の中国語表現を抑え、末尾の指示は近接効果を利用して最後に読ませた一節を抑えます。1 枚だけ入れる場合、末尾に置くとガードレールを止められず、先頭に置くと後ろの 1 千字近い中国語に薄められてしまいます。
- **記憶抽出での言語汚染を防止**：抽出プロンプトの主語表現と長さ単位を言語に追従させます（英語では *characters* ではなく *words* を使う）。このテキストは以降のすべての対話のコンテキストにそのまま注入されるため、言語汚染は累積します。

### 5. バックエンドのエラーメッセージの全面ローカライズ

- **エラーコード + パラメータ化メッセージ**：例外を投げる箇所ではエラーコードと引数だけを宣言し、文言は `core/messages.py` に集約してリクエストの言語に引き当てます。レスポンスボディには `code` フィールドが付随し、フロントエンドでの二次ローカライズと、ログのコード単位での集約（文字列マッチングではなく）に利用できます。
- **ユーザー向け文字列を 24 件新規ローカライズ**：モデルの利用可否と体験モードの制限、メディアアクセスの認可、認証情報の管理、モデルサービスの認証情報不足、管理者操作の応答、モデル同期の結果。
- **Pydantic のバリデーションから中国語が漏れる問題を修正**：フォームのバリデーション失敗時、422 レスポンスボディの `msg` フィールドは中国語がハードコードされていましたが、ローカライズ済みです。
- **`Accept-Language` 標準ヘッダーに対応**：独自ヘッダーではなく標準ヘッダーを使うのは、それが検索エンジンや CDN、そして将来このプロジェクトのフロントエンドを迂回して呼び出すあらゆる呼び出し元にも同時に機能するからです。

### 6. 本番環境 Docker ビルドの厳密性担保

- JSX 属性の中括弧の欠落、Next.js の `metadata` と `generateMetadata` の併存、削除済みモジュールの残存参照、コンポーネントスコープでの hook 欠落など、型と構文の問題を修正しました。
- **辞書と補間型の整備**：4 言語のキー整合性を検証するスクリプト、および補間変数の型を緩和してオプショナルなバックエンドフィールドに対応させ、同じ種類のビルド失敗が繰り返し発生しないようにしました。

## v2.23.0 リリースノート

本バージョンは**入力欄の状態記憶の連動、コンパイルの厳密化、バックエンドアーキテクチャ再構成の切り離し**を一体化した重要なアップデートです。チャット入力欄と過去セッションの状態を正確に復元・再適用できるようにし、本番環境の Docker build 段階で発生していた strict モードの型問題を完全になくしました。またバックエンドのモデルカタログサービスを再構成して重複をなくし、モデル同期の権限を絞り込んでいます。

### 1. チャット入力欄の状態記憶と過去セッションのスマート復元
- **セッション状態の深い連動**：ユーザーが特定のセッションで有効にしたスマート翻訳モード、選択した翻訳先言語など、そのセッション固有の創作状態を、セッションを切り替えたときに正確に判別して復元します。毎回手動で設定し直す必要はありません。
- **「新規チャット」でワンクリック復元**：「新規チャット」をクリックすると、既定のアシスタント入力状態が自動的に復元され、複数のタスクを行き来する会話がスムーズになります。

### 2. 本番環境 Docker コンテナビルドの厳密性担保
- **厳密なインデックスアクセスのガード**：本番環境の Docker build 段階で、TypeScript の `noUncheckedIndexedAccess: true` という strict モードにより露見したオブジェクト分割アクセスの危険箇所を厳密にガードし、自動化 CI/CD とコンテナイメージの高速で安定したビルドを保証します。

### 3. バックエンドのモデルサービス再構成と起動タスクの完全な切り離し
- **モデルカタログの読み書き統一**：`catalog.py` に汎用の JSON カタログ永続化とキャッシュ用ヘルパーを切り出して再構成し、言語・画像・動画・音声の 4 大モデルカタログで一貫したファイル I/O 管理を実現し、样板的な冗長コードを削減しました。
- **起動タスクの完全な切り離し**：チャットモデルの全モデル同期ロジックをサービス層へ降ろし、`main.py` のシステム Lifespan 起動ライフサイクルが API ルートの Handler に抱えていた逆向きの依存と脆い引数バインドを解除しました。
- **中核ロジックのモジュール統合**：Media モジュールの画像と動画のストリーミング応答ロジックを統合し、汎用のモデル検証関数を抽象化して、プロジェクトの保守コストを削減しました。

### 4. モデル同期 API の権限絞り込みと UI 対応
- **管理者権限の制限**：すべての全モデルリアルタイム同期 API（`POST /models/sync*`）を管理者のみ呼び出し可能（`get_current_admin`）に格上げし、一般ユーザーが高頻度でリモートベンダーの API を叩くことを防ぎました。
- **フロントエンド設定ページの同期ボタン対応**：各モデル一覧の「リスト同期」ボタンは管理者のみが表示・クリックでき、一般ユーザーの画面は簡潔に保たれます。

### 5. プロジェクトの冗長コードの整理
- フロントエンドから参照されていない廃止済みのペルソナテンプレートと不要な設定を完全に削除し、コードベース全体の清潔さと堅牢性を高めました。

## v2.22.0 リリースノート

本バージョンは**機能アーキテクチャの簡素化とスマート翻訳の学習支援**を軸とした大型アップデートです。操作画面をさらに絞り込み、スマート翻訳などの拡張機能を「+」創作メニューに一本化しました。文法の変形規則の解説と日本語のふりがな注釈を全面アップグレードし、設定でグローバルな共通システムプロンプトをカスタマイズできるようになりました。

### 1. 創作機能を「+」メニューに統一
- **入力領域の簡潔さ**：入力欄の外側にあった独立したモード切り替えバブルを削除し、「スマート翻訳」に加え「画像を生成」「動画を生成」「音声をテキスト化」などの創作機能を、入力欄左側の `+`（プラス）メニューに統一して格納しました。
- **状態を感知する丸ボタン**：スマート翻訳が有効なとき、プラスボタンが多言語アイコンのハイライト状態に自動切替わり、ワンクリックでいつでも解除または既定値に戻せます。

### 2. スマート翻訳と文法学習の全面アップグレード
- **日本語のふりがな注記**：中国語⇔日本語の翻訳モードでは、すべての漢字の直後に必ず平仮名のふりがなが付きます（例：`私(わたし)は日本語(にほんご)を勉強(べんきょう)しています`）。漢字の読みの判別しづらさを完全に解消します。
- **文法の詳細解析と動詞活用**：主要な動詞の基本形、活用規則（連用形・過去形・進行形など）、構文の時制を抽出し、中核文法と定型表現を細分化して解説し、類題による波及分析も提示します。
- **構造の類似した実用例文**：構造が類似した同タイプの自然な例文を 2~3 組自動生成し、語境の説明と組み合わせの解析を付けます。

### 3. 単発翻訳のコンテキスト遮断機構と高速モデルの自動切替
- **割り込みゼロの単発翻訳**：翻訳時は自動的に単発隔離モードを有効にし、長い履歴のマルチターン会話の文脈を持ち込まず、長期記憶の抽出とウェブ検索を強制的に無効化することで、純粋なミリ秒級の即時翻訳を実現します。
- **推奨モデルの自動切替**：スマート翻訳を有効にすると、超高速モデル（`google/gemini-2.5-flash-lite` と `openai/gpt-4o-mini`）が自動的に優先表示され先頭に置かれます。翻訳を終了するか新規セッションを作ると、ユーザーが設定で指定した優先モデルに自動的に戻ります。

### 4. システム共通プロンプト (System Prompt) のカスタマイズ
- **設定センターにグローバルペルソナ設定を追加**：「設定」に「システムプロンプト」セクションを追加し、ユーザーが必要に応じていつでもグローバルな基礎指示をカスタマイズ・編集でき、ワンクリックで標準のアシスタントプロンプトに戻せます。

## 🐱 Apiapia について（ブランドの物語とインスピレーション）

> 「彼女にはエメラルドのように澄んだ瞳があり、静かにキーボードの横に伏せて日夜を送り添えてきた。そして今、彼女はあなたのデジタル世界で決して忘れない叡智のアシスタントへと姿を変えた。」

<p align="center">
  <em>左：原型の猫の実写写真 · 中央：iOS ネイティブ品質の Web App アイコン · 右：サイト内ブランドの円形アバター</em>

**Apiapia** のモデルは、実際に存在する、可愛らしい縞模様の毛並みと碧緑の瞳を持つ飼い猫です。日常の中では、猫は鋭い直感と長い時間の寄り添いによって家族に温もりと安らぎをもたらします。**Apiapia アシスタントシステム**では、その寄り添いに先端 AI の長期記憶と論理的推論の力が与えられました：

- **忘れないあたたかさ**：新しい会話を始めるたびに「記憶を消す」ことを強制されるという通常の LLM モデルの限界に対して、Apiapia は独自のベクトル記憶エンジン（Mem0 OSS + pgvector）を活用し、あなたの仕事の好み、生活習慣、事実の断片を静かに保存し続けてくれます。
- **話すほど理解が深まる**：デバイスをまたぎ、時間帯をまたぎ、関連する事実を自動的に想起するため、毎回自己紹介をやり直す必要がありません。長い付き合いの友人と話すかのように、滞りなく自然にやり取りできます。
- **全デバイスで优雅に表示**：丁寧に手描きされた猫のブランドロゴに加え、モバイル／デスクトップ双方で視覚を全面的に再設計し、技術的な質感と親しみやすさを両立した使用体験を実現しています。

## 🌟 コアコンセプトとアーキテクチャ

1. **フロントエンド／バックエンドの分離と疎結合**：
   - フロントエンドは **Next.js (React 18 + TypeScript + Tailwind CSS + shadcn/ui)** を採用し、Radix プリミティブと CSS 変数によるテーマを基盤に、UI・操作・ストリーミング SSE 描画・モバイル Web App 対応・バージョン自動更新検出を担当します。モバイルは独立した全画面タブ（iOS のセーフエリア補正を含む）、デスクトップは「ナビゲーションバー + 常設セッションサイドバー + 会話エリア + 関連メモリパネル」のレイアウトです。
   - バックエンドは **FastAPI (Python 3.12)** を採用し、LLM のルーティング、長期記憶の抽出ライフサイクル、全ネットリアルタイム検索、文書解析、セッションデータベース、機微な API Key の暗号化を一元的に担当します。

1.1. **4 言語の国際化とローカライズ (v2.24.0)**：
   - **自作の軽量フレームワーク、第三者依存ゼロ**：URL プレフィックスなし。言語の偏好は `localStorage` と同名の Cookie に保存し、UI・バックエンドのエラー・AI プロンプト・記憶抽出の 4 層を同時に切り替えます。言語状態は `Accept-Language` 標準ヘッダーとともに配信され、検索エンジンや CDN、そして将来このフロントエンドを迂回して呼び出すあらゆる呼び出し元にも同時に機能します。
   - **キー名のコンパイル時検証**：`t("...")` のキーはコンパイル時に検証されるリテラル union であり、1 文字でも打ち間違えれば即座にコンパイルエラーになります。4 つの辞書テーブルは構造の整合が強制されるため、書き漏らしが一目で分かります。
   - **3 箇所の切り替え導線**：ログインページのトップバー、デスクトップのトップバー（テーマ切り替えの左）、環境設定 · 外観。選択肢は自言語の自称 + 英語名を並記しており、ユーザーが相互に確認できます。
   - **AI プロンプトの二言語戦略**：フレーム部分（ペルソナ、時刻基準、検索の誘導、排版規範）は言語に追従。推論の罠を防ぐガードレールは中国語版のみを保持します（few-shot 例は中国語固有の推論の曖昧性であり、言語を変えるとアンカーそのものを変えることになるため）。またプロンプトの先頭と末尾に 1 枚ずつ言語指示を注入し、末尾に 1 千字近い中国語が混ざっても出力言語が薄められないようにします。
   - **スマート翻訳の翻訳先言語は UI 言語に追従**：英語 UI なら英語へ、日本語 UI なら日本語へ、繁体字中国語 UI なら繁体字中国語へ。同一言語なら自動的に単方向翻訳へ退化し、簡体字・繁体字も同一言語として扱います。
   - **バックエンドのエラーコード + パラメータ化メッセージ**：例外を投げる箇所ではエラーコードと引数だけを宣言し、文言はリクエストの言語で引き当てます。レスポンスには `code` が付き、フロントエンドでの二次ローカライズとログのコード単位での集約に利用できます。

2. **全モデル対応のスマート自動 Web 検索 (Web Search Engine, v2.3.0)**：
   - **すべてのモデルに等しく**：特定のモデルメーカーの検索機能に依存せず、Claude、GPT、Gemini、DeepSeek はもちろん、ローカルにデプロイした Ollama モデルまで、すべてが自動的にウェブ検索機能を獲得します。
   - **スマート自動判定 (Auto-Decision)**：システムが時効性のあるニュース、天気、為替、株価相場、外部の事実、最新技術情報などのニーズを自律的に判別し、必要なときに自動で検索します。日常の雑談、純粋なコードや論理演算はゼロ遅延・検索なしで保ちます。
   - **3 段階モードを自由に**：「自動判定（既定）/ 強制オン / オフ」をワンクリックで巡回切り替えでき、ユーザーの好みを自動保存します。
   - **Key 不要の多段フォールバック**：Key 未設定時は内蔵の DuckDuckGo 多段非同期検索エンジンとパーサ（html / lite / instant-answer の 3 段、httpx のみで第三者依存ゼロ）を利用し、100% 無料ですぐに使えます。`TAVILY_API_KEY` を設定すると自動的に **Tavily AI のネイティブ検索を主軸、DuckDuckGo をフォールバック**にアップグレードし、検索品質と RAG の関連性が向上します（現在有効なエンジンは `/api/health` の `web_search` フィールドで確認できます）。
   - **リアルタイム検索と出典リンク**：ストリーミング生成の途中で検索中のアニメーションと検索語を動的に表示し、回答の末尾には「🌐 X 件のウェブを参照しました」という折りたたみ可能なカードを永続表示します。ウェブページのタイトル、概要、原ページへのワンクリックリンクを表示します。

3. **長期記憶とチャット履歴の厳格な分離**：
   - **チャット履歴**：PostgreSQL の `conversations` と `messages` に完全保存され、履歴の追跡とコンテキストの復元に使われます。
   - **長期記憶 (Mem0 OSS 2.2.1)**：**pgvector** ベクトルデータベースに独立して保存され、セッションをまたいで個人の好み、生活習慣、事実を自動的に想起します。
   - **作成時間と新しい順での表示 (v2.2.0)**：すべての長期記憶に秒単位まで正確なタイムスタンプ（`YYYY-MM-DD HH:mm:ss`）を自動記録し、既定では新しい順（降順）に並べます。
   - **1 列の詳細リスト (v2.2.0)**：大量の事実を表示するために設計された、1 列構成のレスポンシブなワイドリスト。最も豊富な内容の詳細を表示し、行内での素早い編集と 1 件単位の正確な削除に対応します。
   - **ADD-only 特性への対応**：Mem0 OSS 2.2.1 の特性に合わせ、古い事実が自動的に上書きされることを前提とせず、Web ページ上で直接閲覧・編集・削除でき、**ワンクリックで JSON エクスポート**して個人データを完全に自分で管理できます。

4. **セッションの整理とピン留め管理 (v2.6.0)**：
   - **ピン留めグループ表示**：重要な過去セッションをワンクリックでピン留めでき、ピン留めしたセッションは独立したグループにまとめられ、ハイライト表示します。
   - **柔軟な並べ替え**：ピン留めしたセッションはドラッグで並べ替えでき、上へ／下への移動による微調整も可能です。優先度順にタスクを整理できます。
   - **軽量な UI 操作**：操作ボタンは常に見える状態で、操作は簡潔で直感的です。

5. **サイト全体の shadcn/ui コンポーネント規約と体験の再設計 (v2.7.0)**：
   - **統一された軽量 ActionTooltip**：サイト全体のサイドバー、ツールバー、操作バルーン、管理エントリに、応答の速いフェードイン演出付きの `<ActionTooltip>` を一括導入しました。
   - **管理バックエンド (Usage & Audit) の標準化アップグレード**：データテーブルをネイティブの `<tr>`/`<td>` から標準の shadcn `<Table>` コンポーネント群へ全面移行し、監査ドロワーとスムーズなタッチコンテナを組み込みました。
   - **設定センターとアクセシビリティ (A11y)**：標準に準拠した連続スライダー `<Slider>` を導入し、モデルセレクターは Popover Combobox を採用。イベントの分離を最適化し、ドロップダウンのスクロールの透過やカクつきを完全に解消しました。
   - **公式ブランドとアバターシステム**：サイト全体のナビゲーションバー、ログインの歓迎画面、空状態のガイダンス、モバイルのトップバーに Apiapia の公式マスコットロゴを全面導入しました。

6. **モデルの疎結合 (LLM Adapter) とマルチモーダル対応**：
   - 統一インターフェース `LLMProvider` を抽象化し、**OpenAI、OpenRouter、Anthropic Claude、Google Gemini、ローカル Ollama** などにネイティブ対応します。
   - **OpenRouter にネイティブ対応**：OpenRouter の Key が 1 つあれば、フロントエンドからワンクリックで Claude 3.7 / 3.5 Sonnet、GPT-4o、DeepSeek V3 / R1、Llama 3.3、Gemini 2.5 などの膨大なモデルを切り替えられます。
   - **マルチモーダルとファイル解析**：画像のアップロード、PDF、Word、TXT、Markdown などのドキュメントにネイティブ対応し、文字を自動で抽出してコンテキストに注入します。画像はフルスクリーンのライトボックスで拡大でき、原寸画像のダウンロードにも対応しています。
   - モデルを切り替えても長期記憶は失われません。

7. **強制的なセキュリティとプライバシー方針**：
   - **強制的 ID 分離**：すべての API における `user_id` は検証済みの JWT から取得し、フロントエンドから渡された `user_id` を決して信用しません。
   - **信頼できないコンテキストの防御**：想起された長期記憶は Prompt レベルで信頼できない背景情報として包み込み、Prompt Injection によるシステム指示の乗っ取りを防ぎます。
   - **API Key の暗号化保存**：ユーザーが設定したモデル認証情報はバックエンドで Fernet 対称暗号化してデータベースに保存し、フロントエンドには決して平文を返しません。

## 📦 クイックデプロイと起動

プロジェクトは完全にコンテナ化されており、Docker Compose を使うだけでサーバー或个人マシン上でワンクリック起動できます。オーケストレーションには標準のヘルスチェックプローブが統合されており、サービスの滑らかな起動を保証します。

### 1. 環境変数の設定

環境変数のテンプレートをコピーします：

```bash
cp .env.example .env
```

実際の環境に合わせて `.env` に設定項目を記入します（起動後に Web フロントエンドの設定ページから設定することもできます）。

**設定項目の完全な一覧と個別説明は `.env.example` を参照してください。** そこには各項目の既定値と変更の影響範囲も記載されています。原則は **必須なのは `POSTGRES_PASSWORD` だけ** で、空のままにしておけば `backend/app/core/config.py` の既定値が使われます。行を削除することは既定値を入れることと同じ意味です。よって、実際に変更したい行だけ書き換えれば十分です。

個別に説明しておく価値のあるもの：

- `POSTGRES_PASSWORD`: **唯一の必須項目**。データベース接続文字列は `POSTGRES_*` から自動的に組み立てられるため、`DATABASE_URL` を手で書く必要はありません（書いてはいけません）。パスワード中の `@` `/` `:` は自動的にエスケープされます。アプリがこの compose 以外のデータベースに接続する必要がある場合にのみ、`DATABASE_URL` / `MEM0_DATABASE_URL` を明示的に設定してください。
- `SECRET_KEY`: JWT の署名鍵。**これを切り替えると全ユーザーがログアウトされます**
- `API_KEY_ENCRYPTION_KEY`: データベースの API Key の対称暗号鍵。**これを切り替えると保存済みのすべての Key が復号できなくなり、ユーザーが再入力するしかなくなります**
- `ADMIN_EMAIL` / `ADMIN_USERNAME`: 公開デプロイでは強く設定することを推奨します。設定しない場合、**最初に登録したユーザーが管理者になります**
- `POSTGRES_HOST_PORT` / `BACKEND_HOST_PORT` / `FRONTEND_HOST_PORT`: ホストのポートマッピング。既定値は `5432` / `8000` / `3000`。ポートが使用中の場合はここを変更してください。`docker-compose.yml` を触る必要はありません
- `APP_VERSION`: サービスのバージョン番号。既定では `VERSION` ファイルを読み込みます。**リポジトリルートの `VERSION` と `frontend/package.json` と一致させる必要があります**——三者は同じ成果物として配布されます
- `OPENROUTER_API_KEY`: OpenRouter の統合 LLM API キー。**チャット、記憶、音声で共用します**
- `TAVILY_API_KEY`: Tavily のウェブ検索キー（https://tavily.com で無料申請、月 1000 回。空の場合は無料の DuckDuckGo のみを使用）
- `TAVILY_SEARCH_DEPTH`: 検索の深さ `advanced`（精度重視）/ `basic`（高速）。既定は `advanced`
- `NEXT_PUBLIC_API_URL`: 空のままにすれば同一オリジンのプロキシ `/api/backend` を使うため、サーバー IP の設定もクロスドメインの問題もありません。**純粋な静的エクスポート（Cloudflare Pages）の場合のみ**設定が必要です。その場合はバックエンド側の CORS でフロントエンドのドメインを許可してください
- `STT_MODEL` / `TTS_MODEL`: **コードレベルのフォールバック定数であり、デプロイ設定ではありません**（`backend/app/core/config.py`）。アカウントで音声設定を一度も開いていない場合や、初回にカタログを同期する前の場合にのみ、送信する値があります。日常的な利用は設定ページで選ぶため、ここを変更する必要はありません（すべきでもありません）
- `TTS_VOICE`: 任意。特定の音色をグローバルに固定します（既定は空 = カタログ内のそのモデルの最初の音色を使用）。**設定は不要です**——音色リストを公開していないモデル（Fish Audio / Seed Audio 系）は `voice` フィールドを自動的に省略し、provider 側の既定音色を使います。モデルとの結合が強い項目で、設定したモデルのほうが受理しない場合は、エラーではなく無視されます
- `FREE_AUDIO_MODELS`: 無料音声モデルをカンマ区切りで指定します。体験モードのアカウントで使用します（`FREE_IMAGE_MODELS` と同じ性質）。多くのモデルはゼロ価格から自動判別できますが、価格 API が無料枠を公開していない場合のためにこの項目があります
- `SPEECH_MAX_AUDIO_BYTES`: 1 回の音声テキスト変換における音声サイズの上限。既定は 25MB（OpenRouter の multipart 上限に一致）
- `SPEECH_MAX_TEXT_CHARS`: 1 回の音声合成におけるテキスト長の上限。既定は 4000 文字

> **設定は 1 箇所だけに書く。** `docker-compose.yml` はイメージ、ポート、ボリューム、ヘルスチェック、サービスの起動順序のみを担当し、業務設定はすべて `.env` から与えます。`.env` に書いていない項目は `backend/app/core/config.py` の既定値にフォールバックします。以前は同じ既定値が compose、`config.py`、`.env` の 3 箇所に重複して書かれており、データベースパスワードも 3 箇所に重複していました。この重複こそが、パスワード変更時に 1 箇所だけ変更を忘れてデータベースに接続できなくなる原因でした。

> **ローカル開発のリロード**：`docker-compose.yml` には `--reload` を付けていません（サーバーでは不要だからです）。必要な場合は `docker-compose.override.yml` を新規作成して `backend.command` を上書きしてください。Compose が自動的にマージするため、本体は変更不要です。

> 音声認識と音声合成は**互いに交わらない 2 系統のモデル**です（OpenRouter の `output_modalities=transcription` と `=speech` が返す集合には共通部分がありません）。そのため設定ページは独立した 2 つのドロップダウン、データベースも `stt_model` / `tts_model` の 2 フィールドになっています。
> **音声形式はサーバー側でネゴシエート**：各モデルがサポートする形式は一致しません（Gemini TTS は pcm のみ、Mistral Voxtral は mp3 のみ）ので、フロントエンドが要求する mp3 は希望値にすぎません。モデルが拒否した場合は自動的に別の形式へ切り替えて再試行し、その結果を記憶します。ブラウザに返されるのは常に再生可能なコンテナであり、裸の pcm は WAV にラップされます（サンプリングレートはレスポンスヘッダー `audio/pcm;rate=…;channels=…` から取得し、推測しません）。
> モデルカタログは `backend/app/synced_audio_models.json` に永続化され、設定ページの「リスト同期」をクリックしたとき、またはバックエンドの起動時にのみ更新されます。言語 / 画像 / 動画カタログの扱いと完全に同じで、リクエスト経路上でのリアルタイムカタログ照会は行いません。
> 音声機能は既存の `OPENROUTER_API_KEY` を再利用するため、追加のキー申請は不要です。未設定の場合、ヘルスチェックの `speech` フィールドには `no OpenRouter key` と表示されます。

### 2. Docker コンテナクラスタのワンクリック起動

```bash
docker compose up --build -d
```

Compose が次の 3 つのサービスを順番に起動し、連携させます：
- `postgres`: pgvector 拡張を備えた PostgreSQL 17 コンテナ。永続化ボリューム `postgres_data` を備えています。
- `backend`: FastAPI バックエンド。ヘルスチェック机制を備え、拡張の有効化、テーブルスキーマの同期、Mem0 の初期化を自動で行います。
- `frontend`: Next.js の独立実行コンテナ。バックエンドが Healthy になるまで自動的に待ってから起動し、`3000` 番ポートを待ち受けます。

### 3. アプリケーションへのアクセス

- **Web UI**：`http://localhost:3000`
- **バックエンド API ドキュメント (Swagger)**：`http://localhost:8000/docs`
- **ヘルスチェック API**：`http://localhost:8000/api/health`
  実際のプローブ結果を返します。データベースに到達できない場合は **503**（`database` フィールドに例外の種類、`status` は `degraded`）を返し、Docker の healthcheck がこれに基づいてコンテナを unhealthy としてマークします。`mem0_oss` フィールドは、長期記憶に利用できる LLM 認証情報が設定済みかどうかを示します。

> 本番デプロイでは手前にリバースプロキシを置き HTTPS を有効化するとともに、`.env` の `SECRET_KEY` と `API_KEY_ENCRYPTION_KEY` をランダムな値に差し替えることを推奨します。`.env.example` に入っている 2 つは公開済みのサンプル値で、誰かが手に入れたらログイントークンを偽造したり、データベース内の API Key を復号したりできます。

## 💾 データ永続化とバックアップ

プロジェクトは `docker-compose.yml` で 2 つの名前付きデータボリュームを定義しています：
- `postgres_data`: PostgreSQL のユーザーテーブル、セッションテーブル、メッセージテーブル、および Mem0 の pgvector ベクトル集合を保存します。
- `mem0_data`: Mem0 のローカル履歴データベースを保存します。

データのバックアップ例：
```bash
docker exec -t apiapia_postgres pg_dump -U postgres apiapia > backup_$(date +%Y%m%d).sql
```

データの復元例：
```bash
cat backup_xxx.sql | docker exec -i apiapia_postgres psql -U postgres -d apiapia
```
