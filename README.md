## v2.20.0 发布说明

本版本是一次**语言学习交互与输入模式扩展**升级。新增了全语种交互式「单词卡片 (WordCard)」与点读发音系统，同时在聊天输入框新增快捷模式选择器，支持一键切换「词汇导师」等专属学习与工作模式。

### 1. 全语种单词学习卡片 (WordCard)

- **多语言交互卡片**：支持英语、日语、法语、德语、西班牙语、韩语等全语种学习排版，呈现单词标题、音标/假名、词性释义、经典双语例句、核心短语及语法注意点提示盒。
- **单词与例句独立点读发音**：调用项目内置的语音合成模型（TTS），点击单词专属小喇叭单独发音，点击例句独立发音，支持浏览器原生语音 API 优雅降级与本地播放缓存。
- **视图切换与一键复制**：卡片支持在「卡片视图」与「代码视图」间平滑切换，支持一键复制单词与原格式。

### 2. 输入框快捷模式选择器

- **常驻快捷按钮**：在输入框左侧加号按钮旁新增模式切换按钮，保持圆钮视觉风格，无需进入设置页即可一键切换角色模式。
- **丰富模式支持**：内置「词汇导师（全语言点读卡片）」、「简洁直接」、「严谨学术」、「创意灵感」、「编程专家」等多重工作模式。
- **状态感知与一键重置**：选中模式后输入框上方出现状态提醒横幅，并支持一键恢复为默认助手。

### 3. 设置页面清爽优化

- 移除了原设置页繁琐的人设配置，使设置主视图聚焦于核心模型、采样温度与记忆系统。

## v2.19.0 发布说明

本版本是一次**智能多维联网检索与引用交互**全面升级。将联网搜索从原本单次仅参考 5 个网页的单一模式，升级为多维度并发扩展、跨语言一手信源探测、行内实时链接引用与多层级排版体系。

### 1. 深度检索扩容与多关键词并发 (Multi-Query Expansion)

- **参考源容量大幅扩充**：单次联网搜索的参考网页上限由原先固定的 5 条扩充至 **15 ~ 20 条**；Tavily 接口深度上限放宽至 20 条，DuckDuckGo 抓取层默认容量翻倍。
- **多角度并发检索**：大模型根据提问复杂度自动拆解 1~3 个互补维度的关键词（如核心主体词、背景研报词、对比评测词），使用 `asyncio.gather` 并发向搜索引擎拉取，总响应时间保持在毫秒级无感知增加。
- **URL 规范化去重与聚合**：跨多个检索词抓取到的网页自动剔除重复域名与相同页面，聚合出前 20 条最相关的优质页面。
- **上下文 Token 保护**：对每个网页 Snippet 施加 400 字符智能截断，总 Prompt 增量严格控制在 2,000 tokens 以内，避免上下文膨胀或注意力迷失。

### 2. 跨语言与本土一手信源策略 (Cross-lingual Retrieval)

- **目标国母语自动探测**：当用户提问明确依赖海外特定国家/地区的一手客观事实（如日本政策、俄罗斯利率、德国职业教育、海外招聘现状）时，大模型自动派生目标国官方母语（日文、俄文、德文等）与国际通用英文的精准检索词。
- **直击一手权威白皮书**：绕过中文互联网常见的中介软文与二手翻译滞后内容，直接抓取目标国官方部门（如日本经产省 METI、俄罗斯央行）与权威招聘平台一手数据，再由大模型阅读后以地道中文综合汇报。
- **防滥用边界约束**：针对纯国内或中文本土事务（如公积金政策、城市天气）严格限制纯中文检索，严禁画蛇添足外文。
- **解析鲁棒性加固**：增加全局贪婪正则 JSON 提取，彻底防御模型输出前置解释客套话导致的格式解析失败与意外降级。

### 3. 行内实时句尾引用与界面层级重构

- **句尾行内实时引用**：废除文末集中堆放的繁琐脚注列表。大模型在陈述具体事实、数据或政策的每句话末尾，直接以 Markdown 链接标注 `[来源: 网站名](URL)`，读者在阅读过程中即看即点，跳转体验极其平滑。
- **排版层级重新梳理**：前端折叠的「参考了 N 个网页来源」交互面板在流式生成与历史记录中均调整至最上方，形成 **「参考网页面板 ➔ 深度思考过程 ➔ 回答正文（句尾内嵌来源）」** 的自然逻辑流。

## v2.18.0 发布说明

本版本是一次**语音能力全栈接入**升级。通过 OpenRouter 的 `/audio/transcriptions` 与 `/audio/speech` 两个端点，为 Apiapia 补齐了「说话进来」与「声音出去」两条完整链路，并按语言 / 绘图 / 视频的既有范式，把语音模型纳入目录同步与设置页管理体系。

### 语音转文字：录音即输入 (Speech-to-Text)

- **麦克风按钮（发送键旁，常驻可用）**：
  - 任意模式下均可点击录音，无需切换模式；
  - 录音中在输入框左侧显示**计时与实时音量条**——音量表不是装饰，麦克风权限被拒、设备静音、选错输入设备时它都不动，一眼可辨「没录上」而非等一个自信的空白转写；
  - **60 秒自动截断并转写**：OpenRouter 上游约 60 秒的处理超时是硬约束，到点自动停止，录到的部分照常转写而非整段作废；
  - 浏览器录音格式自动适配（Chrome/Edge/Firefox 为 webm/opus，Safari 与 iOS 为 m4a）。
- **「音频转文字」上传入口**：
  - 「+」创作菜单新增该项，支持 `wav / mp3 / m4a / webm / ogg / aac / flac` 多选上传。
- **转写结果只填入输入框，不自动发送**：
  - Whisper 会把名字与数字转成看似合理的内容，自动发出不可挽回；多按一次回车的代价远小于此。

### 朗读：文字转语音 (Text-to-Speech)

- **双侧朗读按钮**：
  - 助手回答与**用户提问**的操作栏均新增「朗读」按钮；
  - 用户提问在取文时先过滤附件标记（`stripAttachmentMarkup`），避免把内嵌图片的 base64 编码当文字念出来；
  - 全局播放槽互斥：在任意一条朗读未结束时点击另一条，前者立即停止，不会两个声音叠加。
- **长文本分段合成**：
  - 超过单次字数上限的回复按句末标点切块、逐段串行合成播放，接缝不可闻；
  - markdown 在合成前被剥除（代码块、表格、LaTeX、图片链接、标题符号），避免朗读出一串结构噪声。

### 语音模型目录与设置页 (Speech Model Catalog)

- **独立模型目录**：
  - 目录持久化于 `synced_audio_models.json`，仅在设置页点击「同步列表」或服务启动时刷新，请求链路不做实时查询——与语言 / 绘图 / 视频目录的处理方式完全一致；
  - **识别与合成是两族互不相交的模型**（OpenRouter 的 `output_modalities=transcription` 与 `=speech` 返回的集合无交集），因此目录项带 `capability` 标签，设置页据此拆成两个独立下拉。合成一个列表必然有一半选项用不了。
- **设置页「语音模型」区块**：
  - 「语音识别」与「语音合成」双下拉 + 一键「同步列表」，体验模式账号仅显示免费项；
  - 选错族会被明确拦截提示（「这是语音识别模型，不能用于语音合成」），而非丢给上游报一个语焉不详的错误。
- **模型只由账号设置决定**：
  - 前端**永远不传模型名**，`/speech/*` 一律从 `user_settings.stt_model / tts_model` 解析，请求侧指定模型将构成未鉴权的越权计费途径；
  - 因此语音模型**不在 `docker-compose.yml` 中配置**，部署侧写入只会是一个与用户选择相矛盾的全局覆盖。

### 音频格式协商与容器封装 (Format Negotiation)

- **按模型能力自动适配**：
  - 各 TTS 模型支持的格式并不一致：Gemini TTS 只接受 `pcm`，Mistral Voxtral 只接受 `mp3`。前端请求的 `mp3` 仅为偏好；被拒绝时服务端自动改用另一种格式重试并记住结果——**每个模型每个进程只浪费一次请求**。
- **PCM 实时封装为 WAV**：
  - 浏览器无法播放无容器裸 PCM，但原生支持 WAV；
  - **采样率与声道数从响应头 `audio/pcm;rate=…;channels=…` 解析，不做猜测**——猜错即变调播放。
- **音色解析的自适应**：
  - 部分模型（Fish Audio / Seed Audio 系）在目录中**不公布音色列表**，而这恰恰是唯一允许省略 `voice` 字段的一类；服务端据此省略该字段并采用供应商默认音色，**无需任何额外配置**。

### 依赖与部署

- 新增 `python-multipart` 依赖（FastAPI 解析 `multipart/form-data` 的必要条件），录音以 multipart 上传而非 base64，避免二进制被额外膨胀三分之一；
- 语音功能复用既有的 `OPENROUTER_API_KEY`，无需申请新的密钥；
- 健康检查新增 `speech` 字段，直接报告目录状态（`catalog not synced` / `26 stt / 32 tts catalogued` / `no OpenRouter key`），而非报一个谁都没在使用的模型名。

## v2.17.0 发布说明

本版本是一次**AI 视频生成全栈集成、创作模式面板与输入交互革新**升级。不仅全面接入了基于 OpenRouter 的 AI 视频大模型生成与持久化管道，还对输入框左侧创作功能菜单进行了系统性整合重构，让对话、生图、生成视频与联网检索的使用体验更加丝滑高效。

### AI 视频大模型生成与媒体持久化管道 (AI Video Generation Engine)

- **OpenRouter 视频大模型生态接入**：
  - 全面支持视频模型异步任务提交、状态轮询与本地媒体安全落盘（如 `gen-vid-*` 任务流水线）。
  - 模型动态参数自适应：根据不同模型规范自动适配 `aspect_ratio`（如 16:9 / 9:16）与支持的时长参数，保障生成任务成功率。
  - **媒体本地持久化与流媒体服务**：生成的视频文件自动落盘到后端本地媒体库（`data/media/videos/{YYYY}/{MM}/{id}.mp4`），提供极速本地流式播放与防外部临时链接失效保护。
- **全新专属 AI 视频卡片渲染**：
  - 聊天气泡内嵌全新 `AiVideoCard` 视频播放组件，支持原生控件、全屏播放、模型来源徽标与一键无损下载视频文件。

### 输入区创作面板与模式联动重构 (Creation Hub & Seamless Mode Sync)

- **Gemini App 风格全宽创作上拉面板**：
  - 输入框左侧「+」号弹窗全面升级为与输入框同宽的自适应大抽屉面板（`ResizeObserver` 精准对齐外缘），配以 `rounded-[26px]` 超大圆角、`backdrop-blur-2xl` 毛玻璃与弥散光影。
  - **顶部「相册 / 相机 / 文件」三联操作岛**：
    1. **相册**：蓝色高亮胶囊，专一快速多选系统图片；
    2. **相机**：翠绿高亮胶囊，移动设备（手机/PWA）支持直接唤起系统后置摄像头取景拍照；
    3. **文件**：琥珀色高亮胶囊，支持 PDF、Word、数据表、代码等多类型文档选择。
  - **大字号与富信息能力卡片**：
    - **联网检索**：实时显示动态药丸徽章（`自动判断` / `强制开启` / `已关闭`）与详细工作模式说明；
    - **生成图片 / 生成视频**：大图表、清晰说明与专属彩色高亮边框。
- **输入占位符与顶栏模型全自动联动**：
  - 切换到「生成图片」模式时，输入框提示文字自适应切换为「**描述你的图片**」，顶栏模型选择框实时联动显示当前生效的生图模型；
  - 切换到「生成视频」模式时，输入框提示文字自适应切换为「**描述你的视频**」，顶栏模型选择框实时联动显示当前生效的视频模型；
  - 彻底去除模型名称前冗余的 `[生图]` / `[视频]` 前缀，视觉更加清爽纯粹。
  - 精简顶栏控制区域，移除聊天顶部的多余同步模型按钮，保持界面极简干净。
- **模型选择器触屏焦点优化**：
  - 打开模型选择器时不再默认聚焦搜索框，彻底杜绝移动端/触屏设备打开弹窗时意外顶出系统软键盘遮挡视线的问题。

### 权限安全分级与启动自动化 (Access Control & Auto-Sync)

- **体验模式账号权限分级管控**：
  - 针对无全量模型权限的体验账号，前端视频生成选项置灰并友好引导联系管理员开通；
  - 后端接口层（API & 流式处理）全面部署双重 403 权限拦截，彻底杜绝越权产生计费消耗。
- **服务启动自动同步全量模型**：
  - 后端服务容器启动时自动并发拉取并同步对话模型、图像模型及视频模型库，无需手动初始化。

## v2.16.0 发布说明

本版本是一次**智能联网搜索调度、模型自主工具格式防护与交互排版优化**升级。核心将原先依赖静态正则的联网判断全面升级为 ChatGPT (SearchGPT) 级的智能语义研判与搜索词重写体系，并解决了开源模型在无外部工具时发生的格式伪代码泄漏与多余换行符问题。

### ChatGPT 级智能联网搜索调度系统 (SearchGPT-style Autonomous Search)

- **智能意图研判与上下文关键词重写 (`Query Rewriter`)**：
  - 淘汰死板的纯正则表达式判断，引入轻量高效的 LLM 上下文意图分析层。自动结合现实物理时钟基准与多轮对话历史，动态研判问题是否具备强时效性或需要实时资料。
  - **多轮代词消歧能力**：当用户在第二轮输入口语化短问句（如“那它的价格是多少？什么时候发售？”）时，自动结合上文补齐核心主体，提炼生成精准的高质量布尔搜索词（例如：`苹果 2026 春季新品 售价 发售时间`），搜索精度大幅提升。
  - **毫秒级快速短路机制**：对日常闲聊问候（“你好”）、代码解释、文本翻译润色等任务维持 0ms 本地启发式短路规则，不消耗额外 Token 与延迟；在上游模型异常时自动平滑降级，确保对话流永不断连。

### 模型工具格式防泄漏与全链路净化 (Tool Call Leakage Shield)

- **开源模型伪工具标记全链路拦截**：
  - 针对部分开源模型（如 Qwen2.5 / DeepSeek 等）在缺少联网数据时可能自发输出 `<|tool_call_start|>[google(...)]<|tool_call_end|>` 等未执行伪代码的问题，在**流式窗口拦截器、后端落库过滤、前端 Markdown 渲染器**三层同时部署了净化过滤网，彻底杜绝特殊符号漏出到屏幕。
  - 系统提示词新增强约束负向规则，勒令模型无论何时严禁在正文中泄漏内部工具语法。

### 交互体验与 UI 排版优化

- **联网检索面板折叠体验优化**：
  - 流式回答与历史记录中的“参考了 N 个网页来源”卡片默认保持折叠状态（与“思考过程”保持一致），生成正文时不抢占视线，点击即可平滑展开查看引用的具体网页链接与摘要。
  - 历史记录中的工具调用与底层检索耗时统一收拢进紧凑的折叠面板（`工具调用与检索记录（N 项） ▼`）。
- **提问文本复制多余换行修复**：
  - 解决发送提问或复制历史提问时末尾多出一个换行符的问题。
  - 优化气泡 DOM 节点渲染与复制逻辑，无论是点击「复制提问」按钮，还是用鼠标双击、三击高亮选中提问文字，均保证内容纯净紧凑，杜绝末尾空白行。

### 提示词工程与上下文管理 (Context Engineering)

## v2.13.0 发布说明


本版本是一次**后端**版本。起因是一轮覆盖全部后端代码的通读审计，暴露出若干此前无人发现的问题——其中一类是**正在漏钱的鉴权绕过**，另一类是**不报错、不崩溃、只是安静地不工作**的静默故障。

范围：后端 58 个 Python 文件。删除重复实现与死代码约 600 行，新增 4 个模块承载原本散落各处的安全边界与依赖关系。

### 安全

- **服务端请求伪造（可读型）**：用户在对话里粘贴的 URL 会被**服务端**直接抓取并送进模型上下文，此前**没有任何地址校验**。这意味着任何账号都可以让服务器代为访问云元数据端点（`169.254.169.254`）或内网服务，并把读到的内容通过模型回答完整取回。原实现仅在 `base_url` 上做了防护，而该防护与抓取路径完全分离。现抽出 `app/core/net.py` 统一守卫，覆盖全部三条出网路径，并新增**逐跳重校验**——原先 `follow_redirects=True` 允许一个公网站点 302 到内网绕过首地址检查。同时补上原黑名单的两个绕过：`::ffff:127.0.0.1` 这类 IPv4-mapped IPv6（`IPv6Address in IPv4Network` 因版本不同恒为 `False`，永远匹配不上）、以及 `::/128` 与 `64:ff9b::/96`。
- **体验模式鉴权可绕过**：模型权限判定此前是对模型 id 做**子串匹配**（`"-free" in id` / `"ollama" in id` / `"免费" in id`），而路由判定是另一套规则。两者对同一个字符串给出不同答案——`model="ollama-gpt-4o"` 通过了免费校验（含 `ollama`），随后命中 `gpt` 被路由到 **openai**，直接使用服务端付费密钥。`gpt-4o-free`、`o1-免费版` 同理。现改为**精确 id 查同步目录**，查不到即拒绝（fail closed），免费判定只保留三个可信信号（上游真实定价、`openrouter/free` 内置白名单、由自身同步代码写入的 `provider == "ollama"`）。
- **撤销管理员不收回付费模型权限**：`has_full_model_access` 是 `is_superuser or can_access_all_models`，而降级时只翻转了前者，被降级的管理员因此仍能以计费模型调用服务端凭证。
- **删除两个未鉴权的模型目录接口**：`GET /models/available` 与 `GET /models/openrouter` 从未被前端调用，且均无鉴权——后者同时是一个无速率限制的出网代理。
- **请求体与附件体积闸门**：聊天请求以 base64 内联携带附件，此前无任何上限，且体积检查发生在**完整读入内存之后**。现新增 32MB 请求体闸门（纯 ASGI 中间件，不经过 `BaseHTTPMiddleware` 以免干扰 SSE 长连接），附件按「10 个 / 单文件 20MB / 总量 40MB」三重限制，并在 **base64 解码之前**依据编码长度判定——解码本身就要分配与载荷等量的内存。

### 功能缺陷修复

- **Claude / Gemini / Ollama + 上传图片 = 回答静默截断**：token 用量的回退估算直接对消息列表做 `str.join`，而携带图片时当前轮的内容是**多模态 parts 数组**，`join` 抛 `TypeError`。该行位于 `try` 之外，且这三个 provider 均未定义 `last_usage`（必然走回退分支）——两个条件叠加，触发时流在没有 `done` 事件的情况下中断，前端表现为「回答到一半就没了」。
- **记忆召回阻塞整个事件循环**：`retrieve_relevant_memories` 是同步函数（内部走 `psycopg2` 与同步 openai 客户端），却被直接在 async 端点里调用。单 worker 部署下，一个用户的记忆检索会卡住该进程上的**所有**并发请求。现统一移交 `asyncio.to_thread`。
- **记忆写入与抽取对模型名的处理不一致**：两处各自实现了「优先 OpenAI，否则 OpenRouter」，但其中一处给裸模型名加 `openai/` 前缀、另一处不加。结果是抽取成功而写入失败，报错表现为不透明的 Mem0 异常。默认值恰好自带前缀，所以从未暴露。现合并为单一解析器。
- **用量趋势图与总额对不上**：`daily_trend` 的费用按写死的 `0.20 / 0.80` 每百万计算，而 `model_breakdown` 使用真实定价表。同一份数据两处算出不同的钱——只用 Claude 的用户，图表比总额低约 15 倍。现按 `(时间桶, 模型)` 分组后用同一套定价函数聚合，各桶之和恒等于 breakdown 之和。
- **健康检查从不说实话**：`/api/health` 每个字段都是硬编码字符串，包括 `"database": "connected"`。数据库不可达时后端在 Docker 与任何监控看来都完全健康。现改为实际执行探测，失败返回 **503**；`mem0_oss` 字段也改为反映长期记忆是否已配置可用凭证。
- **数据库初始化失败被静默吞掉**：`init_db()` 异常仅记录日志后继续启动，于是进程存活、每个请求 500、健康检查报告已连接、Docker 永不重启——最坏的失败模式：坏了，但看起来没坏，且不自愈。现改为启动失败并交由 `restart: unless-stopped` 重试。
- **参数约束缺失导致 500**：`temperature` 无范围约束，误填值被原样透传给上游；模型名、用户名等字段无长度上限，超长值撞上数据库列宽后返回带驱动消息的 500 而非指出字段的 422。现统一由 Pydantic 约束。
- **记忆导出的时间戳是错的**：`export_time` 取的是**账号行**最后修改时间——今天导出、但用户上次改设置是六周前，导出文件就标着那个日期。
- **联网检索偏好只写不读**：`web_search_mode` 被持久化到账号，服务端却从不读取，schema 默认值使回落永远到不了。
- **Tavily 告警挂在不可达分支**：一条「未返回 answer 字段」的警告位于 `if/elif` 链的第三个分支，而该场景已在第一个分支处理，永不触发。

### 数据与规模

- **用户上传的图片不再进数据库**：此前以完整 base64 内联存入 `messages.content`，一条消息可达数 MB，进而使消息列表、统计聚合、侧边栏全部为它们并不展示的图片字节付费。现与生成图统一：字节落盘，行内仅保留 id 引用与一份小型元数据记录。
- **会话列表的隐藏放大**：`Conversation.messages` 上一个 `lazy="selectin"` 会在每次加载会话时**自动附加一条查询**把全部消息拉回——侧边栏接口因此承担了 O(全部历史消息体积) 的 IO。移除该配置（该关系在后端从未被访问）。
- **N+1 查询**：置顶重排接口对每个会话单独 `db.refresh()`，而会话本就以 `expire_on_commit=False` 加载，实例已携带新值。

### 工程重构

**分层解耦** —— 此前存在 `api.v1.chat → api.v1.settings → api.v1.models` 的链条，即 **API 层在 import 自己**。这正是 `SUPPORTED_PROVIDERS` 需要写「与 factory 保持同步」注释的原因：规则被抄了一份，因为它自然的归属地够不着。现抽出 `services/catalog.py`（模型目录与权限判定）、`services/model_credentials.py`（用户自带凭证解析）、`services/memory/credentials.py`（记忆凭证解析）。

**重复实现收敛**：

- 会话查询 10 份重复、消息归属校验 2 份、置顶排序时间补齐 5 份 → 各收敛为单一 helper
- 用量趋势图 6 段近乎逐字相同的 SQL → 一个参数化构造器；管理员概览 261 行内联 5 条查询 → 4 个具名查询函数
- 两份逐行相同的「可选 Bearer 依赖」（记忆导出 / 媒体读取）→ `deps.py` 中的单一实现
- Anthropic provider 的 `chat()` 与 `complete()` 各自组装了一遍完全相同的请求体

**死代码清理**：两个未鉴权接口、`duckduckgo_search` 依赖（其上游已改名 `ddgs`，且它只贡献第四级兜底与一次额外串行超时）、三个只写不读的配置项（`MEM0_LLM_PROVIDER` / `MEM0_EMBEDDER_PROVIDER` / `TAVILY_MAX_RESULTS`）、三个从未被读取的请求字段、一个纯转发函数、三个零引用的 re-export 桶文件。同时删除转发性质的 `/stats/admin/conversations/{id}/restore`，恢复操作统一走 `/conversations/{id}/restore`。

**凭据与用量**：Claude / Gemini / Ollama 三家此前**没有** `last_usage` 属性，用量始终依赖启发式估算（中文 1 字 = 1 token），偏差方向还与 GPT 相反，导致跨模型对比不可信。现三家均上报真实用量。

**版本号**：后端此前硬编码 `2.9.0`，而 `VERSION`、前端与 `public/version.json` 已是 `2.12.0`——也就是说 v2.12.0 更新日志里「版本号五处源统一为 v2.12.0」这句话**对后端是假的**。现统一为单一来源（`config.APP_VERSION`，可由 `APP_VERSION` 环境变量覆盖），并修正了上述不实表述。

### 部署注意

本版本有三处**行为变更**，升级前请确认：

- **数据库初始化失败将导致后端启动失败**并被 Docker 重试。若你的 PostgreSQL 用户**没有 `CREATE EXTENSION` 权限**，此前能启动（但所有请求失败），现在会进入重启循环；日志会给出明确提示。`pgvector/pgvector` 官方镜像下 `postgres` 为超级用户，不受影响。
- **`/api/health` 在数据库不可达时返回 503**，Docker 会将容器标记为 unhealthy。Docker 不会因 unhealthy 自动重启，因此这只是报告而非中断。
- **历史消息中的内联 base64 图片仍可正常显示**，但数据库体积不会自动缩小。如需瘦身需单独执行一次性迁移。

## v2.12.0 发布说明

本版本是一次**前端架构重构**版本。重点不是新增功能，而是把长期积累的重复实现收敛为单一事实来源，并修复其中暴露出的若干真实功能缺陷。共触及 68 个文件：新增 32 个、修改 34 个、删除 3 个。

### 布局与交互

- **桌面端记忆侧栏改为常驻**：此前右侧关联记忆栏需要点击顶部 Brain 图标才会展开，与左侧会话栏的常驻行为不对称。现改为在桌面端始终显示于对话区右侧，移动端仍通过 Brain 按钮唤起底部抽屉。相应地移除了桌面端已无作用的记忆按钮，移动端保留。

- **`/chat/[id]` 深链失效**：路由文件从未读取 `params`，组件也没有消费 URL 中的会话 ID。用户在会话列表点「复制链接」得到的地址在外部打开时永远进入默认会话，刷新后同样丢失定位。现已正确解析并恢复会话。
- **`getApiBase()` 绕过同源代理**：该函数的文档说明浏览器端一律走同源 `/api/backend` 代理以规避 CORS，实际实现却在 `NEXT_PUBLIC_API_URL` 非空时直连后端绝对地址。开发环境一旦设置该变量便同时引入 CORS 失败与硬编码 IP 泄漏风险，文档与行为长期不一致。现按文档描述收口。
- **时间字段优先级相反**：记忆库页面优先显示 `created_at`，聊天侧栏优先显示 `updated_at`。同一条被编辑过的记忆在两个界面显示不同时间戳，看上去像数据不一致。现统一为「有编辑时间则显示编辑时间」。
- **深色主题下错误页闪白**：`global-error` 作为根布局的兜底错误边界，硬编码了白色背景，深色主题用户遇到致命错误时会先看到一片纯白。现改为使用主题变量。

### 历史版本：v2.11.0 发布说明

本版本是一次以**安全**与**可访问性**为核心的修复版本。前端经历了一次全量审计，共修复 3 项安全缺陷、3 项功能性故障与 40 余项无障碍、移动端适配与样式失效问题；同时完成导航收敛与模型选择器合流等工程重构，删除约 800 行重复实现。

审计发现的问题按风险分三批修复：第一批为样式与移动端适配的静默失效，第二批为安全与无障碍，第三批为重复代码收敛。三批均不涉及后端协议变更。

### 安全

- **SVG 代码块 XSS 彻底封堵**：模型输出的 ` ```svg ` 代码块此前经 `dangerouslySetInnerHTML` 直接注入页面，仅过滤 `<script>` 标签。由于模型会原样回显用户粘贴的内容，等同于将外部文本直接写入 DOM，`<img onerror>` / `<svg onload>` / `<foreignObject><iframe src="javascript:">` / `xlink:href="javascript:"` 均可执行。现改为 `sandbox=""` 空沙箱 iframe 渲染（脚本、表单、弹窗全部禁用，SVG 仅可作为静态图像显示），并从 `viewBox` 推断宽高比以完全保持原有预览观感。
- **解除移动端缩放锁定**：移除 `viewport` 的 `maximumScale: 1` 与 `userScalable: false`，修复 Android Chrome 下违反 WCAG 2.1 SC 1.4.4（Resize Text）的问题——低视力用户此前无法放大任何内容。保留 `viewportFit: "cover"`，安全区数值仍可正常获取。
- **登录态不再被网络抖动摧毁**：`refreshUser` 原先在**任意**异常分支下都无条件删除本地 token，一次后端 5xx、网关超时或瞬时断网即造成不可恢复的登出（登录页无法解释原因，用户只能重新输密码）。新增 `ApiError` 携带 HTTP 状态码，现在仅 401 / 403 才清除凭据，5xx 与网络故障保留登录态并静默重试。

### 稳定性

- **三层错误边界**：补齐 `error.tsx`（路由级，含重试与错误编号）、`global-error.tsx`（根布局级，兜住全局 Provider 抛错）、`not-found.tsx`。此前聊天页（1000+ 行、30 余处状态更新、手写 SSE 解析）任一处渲染异常即导致整站白屏且无任何恢复入口。
- **流式输出不再被覆盖**：`useRefreshOnResume` 的「页面重新可见」触发路径此前绕过了 `enabled` 判断，导致**流式生成过程中切回对话页会用服务端快照覆盖正在生成的内容**。现已将守卫下沉到两个触发点共用的执行函数。
- **清理失效控件**：移除桌面工具栏中调用 `md:hidden` 容器、在桌面端可见可点却毫无反应的汉堡按钮（它还会顺手改写 URL）；移除 `Sidebar` 中永不打开的移动端抽屉分支及其抓手、关闭按钮等约 40 行不可达代码。

### 无障碍（此前键盘操作大面积不可用）

- **会话列表键盘可达**：会话行此前是 `<div onClick>`，无 `role` / `tabIndex` / 键盘事件，**键盘用户一个会话都打不开**。现标题渲染为真实 `<button>` 并配 `aria-current`，同时保留整行可点击的鼠标手感。刻意未给外层加 `role="button"`，因为行内还嵌有 4 个操作按钮，而 button 角色不允许交互后代。
- **模型选择器按 ARIA combobox 重写**：此前选项是纯 `<div onClick>`，无 `role`、无 `tabIndex`、无方向键处理，**键盘完全无法切换模型**。现两个选择器均补齐 `aria-haspopup` / `aria-controls` / `aria-autocomplete` / `aria-activedescendant`，支持 ↑↓ Home End Enter 并自动滚动高亮项进可视区；焦点在打开时直达搜索框（此前 `searchInputRef` 声明后从未被 focus）。同时修复关闭时搜索词未清空导致「重开只见旧结果」的缺陷。
- **流式输出可被读屏感知**：消息区接入 `role="log"` + `aria-live` + `aria-busy`，并新增独立状态播报区（正在思考 → 正在生成回答 → 回答已完成）。其中 `aria-relevant="additions"` 是关键——若不限定，流式气泡内逐字变化的文本会被反复朗读，实际效果比完全不播报更糟。
- **导航当前位置语义**：桌面与移动导航补 `aria-current="page"`；修复导航项两个标签 `span` 同时存在于 DOM 导致读屏念出「对话对话」「记忆库记忆」的重复朗读。聊天输入框补 `aria-label`（此前仅靠会随输入消失的 placeholder）。

### 移动端与响应式

- **刘海与安全区适配**：移动端顶栏此前完全没有 `env(safe-area-inset-top)` 补偿，标题与头像被 iOS 状态栏压住（注释声称已适配但实现缺失）。全局补齐 `--sat` / `--sal` / `--sar` 三个安全区变量的实际使用——它们此前定义了却零引用，横屏刘海与 Android edge-to-edge 下左右两端也会钻到圆角里。
- **修复平板记忆面板死区**：记忆侧栏此前需 ≥1024px 才显示，而它的触发按钮却在 ≥1024px 隐藏——**768–1023px 区间两者都不渲染**，关联记忆面板完全无法打开，且该区间内它以底部弹层形态出现在桌面布局上。现统一为 `md` 断点。
- **修复断点判定口径**：`/memory`、`/usage`、`/settings` 使用 `window.innerWidth < 768` 判断移动端，但该值**包含滚动条**而 Tailwind `md` 媒体查询不包含，导致 768px 宽的桌面窗口下同时出现移动端外壳与桌面视图、却没有任何导航。已抽出 `lib/mediaQuery.ts` 统一走 `matchMedia`，并让 768 这个数字只有一处定义。
- **修复 iOS 输入聚焦缩放**：全局仅对 `input[type=text|search]` 与 `textarea` 强制 16px，**邮箱与密码字段仍会触发 Safari 聚焦缩放且不回退**，撑破登录页居中布局。改为覆盖全部可输入控件（排除复选框、单选、按钮等非文本控件，尺寸不受影响）。

## 🌟 核心理念与架构特点

1. **前后端分离与解耦**：
   - 前端采用 **Next.js (React 18 + TypeScript + Tailwind CSS + shadcn/ui)**，基于 Radix 原语与 CSS 变量主题，负责 UI、交互、流式 SSE 渲染、移动端 Web App 适配及版本自动更新检测。移动端为独立全屏页签（含 iOS 安全区补偿），桌面端为「导航栏 + 常驻会话侧栏 + 对话区 + 关联记忆栏」布局。
   - 后端采用 **FastAPI (Python 3.12)**，统一负责 LLM 路由调度、长期记忆提取生命周期、全网实时检索、文档解析、会话数据库及敏感 API Key 加密。

2. **全模型通用智能全自动联网检索 (Web Search Engine, v2.3.0)**：
   - **全模型普惠**：不依赖特定模型厂商的联网功能，无论是 Claude、GPT、Gemini、DeepSeek，还是本地 Ollama 部署的模型，全部自动具备联网搜索能力。
   - **智能自动判定 (Auto-Decision)**：系统自主识别时效性新闻、天气、汇率、股票行情、外部事实、最新技术资讯等需求，按需自动搜索；日常闲聊、纯代码或逻辑运算保持零延迟免搜。
   - **三档模式随心控**：输入框支持「自动判定 (默认) / 强制开启 / 关闭」一键循环切换，并自动持久化用户偏好。
   - **多级免 Key 高可用**：未配置 Key 时内置 DuckDuckGo 多级异步搜索引擎与解析器（html / lite / instant-answer 三级，纯 httpx 零第三方依赖），100% 免费开箱即用；配置 `TAVILY_API_KEY` 后自动升级为 **Tavily AI 原生搜索为主 + DuckDuckGo 兜底**，搜索质量与 RAG 相关性更强（`/api/health` 的 `web_search` 字段可查看当前生效引擎）。
   - **实时检索与网页溯源**：流式生成过程中动态呈现检索中动效及检索词；回答下方持久化提供「🌐 参考了 X 个网页来源」交互式可折叠卡片，展示网页标题、摘要与一键直达外链。

3. **长期记忆与聊天记录严格分离**：
   - **聊天记录**：完整保存在 PostgreSQL `conversations` 与 `messages` 中，用于历史溯源与恢复上下文。
   - **长期记忆 (Mem0 OSS 2.2.1)**：独立存储在 **pgvector** 向量数据库中，跨会话自动召回用户的个人偏好、生活习惯与事实。
   - **创建时间与倒序展示 (v2.2.0)**：每条长期记忆均自动记录精准到年月日时分秒（`YYYY-MM-DD HH:mm:ss`）的时间戳，默认按最新优先（倒序）排列。
   - **单列完整列表视图 (v2.2.0)**：专为大容量事实设计的单列自适应宽屏列表，展示最丰富的内容细节，支持行内快速编辑与单条精准删除。
   - **ADD-only 特性适配**：适配 Mem0 OSS 2.2.1 特性，不假设自动覆盖旧事实，支持用户在 Web 页面直接查看、编辑与删除，并支持 **一键导出 JSON** 实现个人数据完全自主。

4. **会话组织与置顶管理 (v2.6.0)**：
   - **置顶分组展示**：支持对重要历史会话进行一键置顶，置顶会话聚合在独立分组中高亮呈现。
   - **灵活排序调整**：置顶会话支持拖拽排序以及上移 / 下移快捷微调，方便按优先级排列任务。
   - **轻量界面交互**：操作按钮常驻可见，交互简洁直观。

5. **全站 shadcn/ui 组件规范与体验重构 (v2.7.0)**：
   - **统一轻量 ActionTooltip**：全站侧边栏、工具栏、操作气泡与管理入口统一接入响应迅速、带淡入微动效的 `<ActionTooltip>`。
   - **管理后台 (Usage & Audit) 规范化升级**：数据表格由原生 `<tr>`/`<td>` 全量升级为标准 shadcn `<Table>` 系列组件，集成审计抽屉与平滑触控容器。
   - **设置中心与无障碍体系 (A11y)**：引入符合标准规范的连续滑块 `<Slider>`，模型选择器采用 Popover Combobox，事件隔离优化，彻底杜绝下拉列表滚动穿透与卡顿。
   - **官方品牌与头像系统**：全站导航栏、登录欢迎页、空状态引导及移动端顶栏全量接入 Apiapia 官方吉祥物徽标。

6. **模型解耦 (LLM Adapter) 与多模态能力**：
   - 抽象 `LLMProvider` 统一接口，原生适配 **OpenAI、OpenRouter、Anthropic Claude、Google Gemini、本地 Ollama** 等。
   - 原生支持 **OpenRouter**：只需一个 OpenRouter Key，即可在前端一键切换 Claude 3.7 / 3.5 Sonnet、GPT-4o、DeepSeek V3 / R1、Llama 3.3、Gemini 2.5 等海量大模型。
   - **多模态与文件解析**：原生支持上传图片、PDF、Word、TXT、Markdown 等文档，自动完成文字提取并注入对话上下文，图片支持全屏灯箱放大与原图下载。
   - 更换模型不丢失长期记忆。

7. **强制安全与隐私准则**：
   - **强制身份隔离**：所有 API 中的 `user_id` 均从经过验证的 JWT 中获取，绝不信任前端传递的 `user_id`。
   - **不可信上下文防御**：召回的长期记忆在 Prompt 层面作为不可信背景资料包裹，防止 Prompt Injection 劫持系统指令。
   - **API Key 加密持久化**：用户配置的模型凭证在后端使用 Fernet 对称加密入库，前端永不返回明文。

## 📦 快速部署与启动

项目已完全容器化，直接使用 Docker Compose 即可在服务器或个人机器上一键启动。编排中已集成标准健康检查探针，保证服务平滑启动。

### 1. 配置环境变量

复制环境变量模版：

```bash
cp .env.example .env
```

根据你的实际情况在 `.env` 中填写配置项（也可以在启动后通过 Web 前端的设置页面进行配置）。

**配置项的完整清单和逐项说明见 `.env.example`**，那里同时标注了每一项的默认值与改动影响。原则是：**只有 `POSTGRES_PASSWORD` 是必填的**，其余留空即采用 `backend/app/core/config.py` 中的默认值，删掉一行等同于填默认值。因此你只需要改动真正想改的那几行。

几个值得单独说明的：

- `POSTGRES_PASSWORD`: **唯一必填项**。数据库连接串由 `POSTGRES_*` 自动拼装，无需（也不应）再手写 `DATABASE_URL`；密码中的 `@` `/` `:` 会被自动转义。只有当应用需要连接本 compose 之外的数据库时，才显式设置 `DATABASE_URL` / `MEM0_DATABASE_URL`。
- `SECRET_KEY`: JWT 签名密钥，**轮换它会让所有人被登出**
- `API_KEY_ENCRYPTION_KEY`: 数据库 API Key 对称加密密钥，**轮换它会让已存的所有 Key 无法解密，用户必须重新填写**
- `ADMIN_EMAIL` / `ADMIN_USERNAME`: 公开部署强烈建议设置，否则**第一个注册的用户会成为管理员**
- `POSTGRES_HOST_PORT` / `BACKEND_HOST_PORT` / `FRONTEND_HOST_PORT`: 宿主机端口映射，默认 `5432` / `8000` / `3000`。端口被占用时改这里，不用动 `docker-compose.yml`
- `APP_VERSION`: 服务版本号，默认读 `VERSION` 文件。**须与仓库根目录 `VERSION`、`frontend/package.json` 保持一致**——三者作为同一份产物发布
- `OPENROUTER_API_KEY`: OpenRouter 统一大模型 API 密钥，**同时供聊天、记忆、语音使用**
- `TAVILY_API_KEY`: Tavily 联网搜索 Key（https://tavily.com 免费申请，每月 1000 次；留空则只用免费 DuckDuckGo）
- `TAVILY_SEARCH_DEPTH`: 搜索深度 `advanced`（准）/ `basic`（快），默认 `advanced`
- `NEXT_PUBLIC_API_URL`: 留空即使用同源代理 `/api/backend`，无需配置服务器 IP，也无跨域问题。**只有纯静态导出（Cloudflare Pages）才需要填**，那时后端 CORS 还需放行前端域名
- `STT_MODEL` / `TTS_MODEL`: **代码级兜底常量，不是部署配置**（`backend/app/core/config.py`）。仅在账号从未打开过语音设置、或首次同步目录之前有值可发。日常使用在设置页挑选，无需也不应当改这里
- `TTS_VOICE`: 可选，全局钉死某个音色（默认留空＝用目录里该模型的第一个音色）。**不需要配置**——不公布音色列表的模型（Fish Audio / Seed Audio 系）会自动省略 `voice` 字段、由 provider 用自己的默认音色。与模型强绑定，若设了此项而当前模型不接受会被忽略而非报错
- `FREE_AUDIO_MODELS`: 逗号分隔的免费语音模型，供体验模式账号使用（与 `FREE_IMAGE_MODELS` 同性质）。多数模型可由零定价自动识别，此项用于定价接口没暴露的免费档
- `SPEECH_MAX_AUDIO_BYTES`: 单次语音转文字的音频体积上限，默认 25MB（与 OpenRouter 的 multipart 上限一致）
- `SPEECH_MAX_TEXT_CHARS`: 单次语音合成的文本上限，默认 4000 字

> **配置只写一处。** `docker-compose.yml` 现在只负责镜像、端口、卷、健康检查和服务顺序，业务配置一律来自 `.env`；`.env` 里没写的项回落到 `backend/app/core/config.py` 的默认值。此前同一份默认值在 compose、`config.py`、`.env` 三处各写一遍，数据库密码在三处重复，正是这种重复导致改密码时漏改、连不上库。

> **本地开发热重载**：`docker-compose.yml` 不带 `--reload`（服务器不需要）。需要时新建 `docker-compose.override.yml` 覆盖 `backend.command` 即可，Compose 会自动合并，主文件不用改。

> 语音识别与语音合成是**两族互不相交的模型**（OpenRouter 的 `output_modalities=transcription` 与 `=speech` 返回的集合没有交集），所以设置页是两个独立下拉、数据库是两个字段 `stt_model` / `tts_model`。
> **音频格式由服务端协商**：各模型支持的格式不一致（Gemini TTS 只接受 pcm，Mistral Voxtral 只接受 mp3），所以前端请求的 mp3 只是偏好。模型拒绝时会自动改用另一种格式并记住结果；返回给浏览器的永远是可播放的容器——裸 pcm 会被包成 WAV（采样率取自响应头 `audio/pcm;rate=…;channels=…`，不猜）。
> 模型目录持久化在 `backend/app/synced_audio_models.json`，只在设置页点「同步列表」或后端启动时刷新，与语言 / 绘图 / 视频目录的处理方式一致；请求链路上不做实时目录查询。
> 语音功能复用已有的 `OPENROUTER_API_KEY`，无需额外申请密钥。未配置时健康检查的 `speech` 字段显示 `no OpenRouter key`。

### 2. 一键启动 Docker 容器集群

```bash
docker compose up --build -d
```

Compose 将按序拉起并协同三个服务：
- `postgres`: 带有 pgvector 扩展的 PostgreSQL 17 容器，配备持久化卷 `postgres_data`。
- `backend`: FastAPI 后端，具备健康检查机制，自动完成扩展激活、数据表结构同步与 Mem0 初始化。
- `frontend`: Next.js 独立运行容器，自动等待后端服务 Healthy 后启动，监听 `3000` 端口。

### 3. 访问应用

- **Web 界面**：`http://localhost:3000`
- **后端 API 文档 (Swagger)**：`http://localhost:8000/docs`
- **健康检查接口**：`http://localhost:8000/api/health`
  返回真实探测结果：数据库不可达时返回 **503**（`database` 字段给出异常类型，`status` 为 `degraded`），Docker healthcheck 会据此把容器标记为 unhealthy。`mem0_oss` 字段反映长期记忆是否已配置可用的 LLM 凭证。

> 生产部署建议在前面加一层反向代理并启用 HTTPS，同时把 `.env` 中的 `SECRET_KEY` 与 `API_KEY_ENCRYPTION_KEY` 换成随机值——`.env.example` 里的两个是公开的示例值，任何人拿到都能伪造登录令牌或解密数据库里的 API Key。

## 💾 数据持久化与备份

项目在 `docker-compose.yml` 中定义了两个具名数据卷：
- `postgres_data`: 存储 PostgreSQL 用户表、会话表、消息表以及 Mem0 pgvector 向量集合。
- `mem0_data`: 存储 Mem0 本地历史数据库。

数据备份示例命令：
```bash
docker exec -t apiapia_postgres pg_dump -U postgres apiapia > backup_$(date +%Y%m%d).sql
```

数据还原示例命令：
```bash
cat backup_xxx.sql | docker exec -i apiapia_postgres psql -U postgres -d apiapia
```
